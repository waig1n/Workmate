# 管理与安全

[English](../en/administration.md) | [简体中文](../zh-CN/administration.md)

通过角色、部门和资源共享规则，为团队建立清晰的 AI 使用边界。本指南介绍账号管理、授权、审批与审计的日常操作。

## 组织与账号

首次初始化创建组织和组织根管理员。默认 `bootstrap_only` 只允许首次初始化注册；`closed` 禁止注册。完成初始化后通过用户管理创建成员，避免共享管理员账号，并保留至少两个可用组织根管理员。

管理操作按具体权限（Permission）及作用范围（Scope）授权。账号管理、角色绑定、部门管理是独立权限。组织管理员可在组织设置修改名称；名称变化不改变组织和资源 ID。

系统阻止移除最后一个处于启用状态的组织根管理员。遇到 `last_root_admin` 时先配置并验证另一个管理员，再执行降级或禁用。禁用账号使其旧 JWT 失效，并为任务提交停止意图；账号已禁用不意味着运行资源已完成清理。

## Scope 与共享

![RBAC + Scope 企业授权边界](../assets/diagrams/access-governance-zh-CN.svg)

组织（Organization）、部门（Department）和个人（Personal）范围用于界定资源归属与授权。部门成员身份、管理职责和资源使用授权分别维护。共享资源不会转移所有权，也不会自动公开凭据。

Skill 和 MCP 在组织库管理，通过显式授权供部门或组织使用。共享 Agent 必须同时检查绑定的 Skill、MCP 和知识库依赖；补充授权需由有权限的管理者确认。共享知识库检索权不自动授予原文下载权。

管理权限、调用者的使用权限、智能体所在范围的资源绑定权限，以及外部服务身份分别检查。共享 MCP 连接使用服务凭据访问外部系统，智能体在 Workmate 内仍以当前调用者身份接受授权检查。管理员也不会因账号管理权限而自动获得个人会话内容。

## 变更与撤销

版本冲突时刷新并核对差异，不盲目重试旧草稿。部门移动影响继承路径，角色委派不能超过操作者授予范围。撤销资源授权会阻止后续准入或审批续跑；已执行的外部操作和已交付内容不会自动撤回。

删除部门或角色可能因引用而被拒绝，先根据返回的阻塞项清理关联。不要通过直接删数据库行绕过权限、版本和最后管理员保护。

## 审批与审计

创建资源、调整权限等平台管理工具操作需要显式确认，“自动执行”（Full Access）模式也遵循此规则。定时等无人值守任务会拒绝需要人工审批的操作。管理审计记录权限和配置变更；工作台的“执行活动”用于查看任务中的工具调用。

管理审计通过 `/api/admin/security-audit-events` 按授权范围查询。审计数据不应包含密码、JWT、完整认证头或 MCP 密钥。排障材料和备份同样需要访问控制。

## 执行环境

默认 Bubblewrap 隔离 Agent 工具进程，服务端凭据不应进入 Agent 环境。Local 后端没有沙箱隔离，只适用于明确接受该边界的环境。发送消息、修改外部系统等操作，应由集成方设置业务幂等和权限规则。队列去重不提供任意外部操作“恰好执行一次”的保证。
