# 支持范围与限制

[English](../en/limitations.md) | [简体中文](../zh-CN/limitations.md)

选择部署方案时，请结合下列支持范围评估运行环境、集成方式和恢复需求。

| 范围 | 支持情况与使用要求 |
|---|---|
| 运行环境 | 默认部署使用 Linux 与 Bubblewrap，需要宿主机支持命名空间及相应容器权限 |
| 沙箱 | 不同后端的隔离、存储、暂停和恢复能力不同；Local 后端不提供沙箱隔离 |
| 横向扩展 | 支持多 Worker 副本与固定多节点部署；同一会话串行执行，扩容需配置存储归属与节点路由 |
| 故障恢复 | 支持满足条件后的显式恢复和可选文件检查点；运行中的任务不会跨机器透明接管 |
| 数据恢复 | 数据库、Core 状态、工作文件和长期记忆分别持久化；文件检查点可能落后于最新修改 |
| 容量与稳定性 | 并发容量受模型配额、数据库、队列、存储及沙箱资源影响，需用实际负载测试 |
| 模型媒体 | 输入格式取决于适配器与供应商端点的共同支持范围，配置后需用实际请求确认 |
| 知识检索 | 文档完成索引后可检索；检索质量需结合业务语料和问题评估 |
| 企业 IM | 各平台分别配置凭据、身份绑定和权限；个人微信为试验功能，主动通知受近期会话上下文限制 |
| 无人值守 | 需要人工审批的操作会被拒绝，任务不会停留在等待确认状态 |
| 成本统计 | 提供用量与费用估算，实际收费以供应商账单为准；不提供收费结算或预算强制控制 |
| 外部操作 | 消息发送、业务写入等操作需要集成方提供幂等处理；结果未知时不会自动重放 |
| 历史资源清理 | 跨节点回收旧工作空间仍有条件限制，无法确认安全清理时会保留资源 |

Workmate 处于活跃开发阶段。正式上线前，请在目标环境验证权限、审批、停止、文件交付和备份恢复，并测试实际使用的模型及外部集成。部署步骤见[部署与运维](deployment.md)，负载测试和故障演练工具见[测试与运维工具](tooling.md)。
